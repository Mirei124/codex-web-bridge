# 项目目标

## 背景

- 机器 A 运行 Codex，保存代码、Codex 配置和原生会话记录。
- 公网机器 B 运行服务端与 WebUI，方便用户从浏览器访问。
- A、B 之间默认网络互通，B 可以通过 SSH 访问 A，不在本项目中实现内网穿透。
- 系统面向单用户，但需要管理多台 A 和多个并行 Codex 线程。

## 核心目标

在 B 上提供一个安全的 WebUI，通过 SSH 管理 A 上的 Codex 线程：

1. 创建线程时，在目标 A 上创建独立 tmux 会话，并在其中启动 Codex 的结构化服务接口。
2. SSH 断开或 B 上的服务重启后，tmux 与 Codex 继续运行；服务恢复后可以重新连接。
3. WebUI 实时展示 Codex 的结构化会话内容与运行状态，并允许用户发送新的消息。
4. WebUI 支持 Codex 的完整交互请求，包括：
   - 计划模式中的问题和选项；
   - 命令执行审批；
   - 文件修改审批；
   - 权限申请；
   - 用户补充信息；
   - 中断当前生成。
5. 支持创建新 Codex 线程、退出当前运行实例，以及按 Codex 线程编号恢复历史线程。

## 生命周期语义

- 一个 Codex 线程对应一个独立 tmux 会话，允许多个线程并行运行。
- “创建”表示新建 Codex 原生线程并启动对应运行实例。
- “退出”或“销毁”表示停止该 tmux 与当前 Codex 运行实例。
- 退出不删除、不归档、不修改 A 上的 Codex 原生会话记录。
- “恢复”表示按 Codex 线程编号重新启动运行实例，并继续已有上下文；也应能重新连接仍然存活的 tmux。

## 安全边界

- WebUI 使用单用户密码认证；服务端只保存密码的安全哈希，不保存明文密码。
- Caddy 负责公网 HTTPS 与反向代理，应用服务只监听 B 的回环地址。
- 应用只信任来自本机 Caddy 的代理协议头。
- 对未确认经过 HTTPS 的请求，应用必须在认证逻辑之前拒绝，不返回登录结果、主机信息、线程信息、对话内容或其他敏感信息。
- 浏览器与服务端之间的实时连接同样只允许安全 WebSocket，并校验登录状态和来源。
- A 上现有的 Codex 登录状态、配置、沙箱与项目权限继续作为实际执行边界，B 不保存 Codex 凭据。

## 完成标准

- B 重启或 SSH 短暂断线不会终止 A 上正在运行的 Codex。
- 用户可以从 WebUI 创建、查看、继续、中断和退出线程。
- 用户可以在 WebUI 完成计划选项、补充信息和各类审批，等待中的线程不会因缺少交互入口而永久卡住。
- 用户可以发现并恢复 A 上已有的 Codex 历史线程。
- 纯 HTTP 或绕过 Caddy 的请求无法登录，也无法获取任何敏感信息。

## 非目标

- 不实现内网穿透或虚拟网络组网。
- 不删除或改写 Codex 原生历史记录。
- 首版不实现多用户、角色权限或团队协作。
- 不通过解析 Codex 终端画面来推断消息、计划或审批状态。
- 不重新实现 Codex 的 Agent、记忆、工具或沙箱能力。
