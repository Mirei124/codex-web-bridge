# Codex app-server protocol verification

The client targets the v2 protocol generated by:

```sh
codex app-server generate-ts --out /tmp/codex-app-server-types
```

The implementation was checked against `codex-cli 0.144.6`. The generated
bindings confirm `initialize`, the `initialized` client notification,
`thread/start`, `thread/resume`, `thread/list`, `turn/start`, `turn/steer`,
`turn/interrupt`, approval requests, and `item/tool/requestUserInput`.

Run the non-mutating installed-binary smoke test manually:

```sh
pnpm --filter @cwb/codex-client smoke
```

It starts `codex app-server` on a temporary loopback WebSocket port, performs
the initialization handshake, and calls `thread/list` with a limit of one. It
does not create a thread, start a model turn, or write to the project. The test
skips with an explicit reason when Codex is absent or loopback binding is denied
by the execution sandbox. Normal `pnpm test` leaves this opt-in test skipped.
